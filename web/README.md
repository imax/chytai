# Chytai web: бібліотека, Discovery, рекомендації

Платформена частина Chytai, окремо від читалки (`server/`): сторінки «Мої книжки», Discovery з публічними
полицями і пошук по всьому. Node + Express, HTML рендериться на сервері, дані в JSON.

- Читачі: власник (WEB_OWNER) лише один із читачів. Його публічна полиця `/reader/<WEB_OWNER_SLUG>` (типово `max`),
  на сторінці книжки блок «У читачів». `/me` бачить тільки залогінений; статус, оцінка й нотатка редагуються лише
  там, на `/me/book/<id>`. Гості не бачать позначок власника на картках і його підписок.
- `server.js` маршрути; `store.js` дані; `db.js` база; `pages.js` HTML; `public/` CSS і JS.
- База: SQLite (`node:sqlite`, нічого ставити не треба) у `DATA_DIR/web/chytai.db`: каталоги полиць з датою, коли
  кожну книжку побачили вперше, бібліотека (книжки, записи читача, підписки), адреси книжок (slug, раз виданий,
  лишається за книжкою) і пошуковий індекс FTS5. Пошук: слова з префіксом, назва важить більше за автора й серію;
  якщо нічого, тріграми (шматок слова) і виправлення одруківок (слова за 1–2 літери з індексу). Старі
  `library.json`, `shelves.json`, `catalog-seen.json` імпортуються при першому старті і стають `*.migrated`.
- `seed/books.json`, `seed/max.json`: одноразовий імпорт Books.md і books-meta.yml з maxua-v3
  (`node web/scripts/import-books.mjs ../maxua-v3`). Далі бібліотека живе в базі.
- `seed/office.json`: паперові книжки в офісі (з фото, 18.10.2026); російськомовні в профіль не додаються.
- `catalogs.js`: джерела полиць (Lobster і Видавництво через WooCommerce Store API; Старий Лев через публічний JSON API свого сайту, разом з e-book і книжками партнерів). Для сайтів без API є `sitemapProducts` (sitemap і сторінки книжок), але тільки там, де сайт не ставить захист від ботів: Віхола його ставить (JS-перевірка і 429), тож її немає. Нове джерело з `draft: true` бачить тільки залогінений власник, поки Макс його не подивиться. Там же як продукт стає
  карткою, і щоденне оновлення: перший запит дня, що бачить полиці старші за добу, запускає його у фоні (машина
  спить між візитами, тому таймер не підходить); власник може примусово `POST /api/refresh`. Результат у базі, джерело, що впало, лишає попередні дані. «Нове» = з'явилося після
  `baseline` у seed (дата першої збірки) і не старше 30 днів, або позначене новинкою на сайті джерела.
- `catalogs/*.json` нормалізовані каталоги для seed; `node web/scripts/build-shelves.mjs` збирає з них `seed/shelves.json`.
  Standard Ebooks прибрали 19.10.2026: фокус на українських каталогах.
- Твір і видання: однакові книжки на полицях (той самий ISBN або автор+назва) і в бібліотеці (точний збіг назви
  чи оригінальної назви) склеюються в одну; `seed/matches.json` для пар, які збіг назв пропускає або плутає.
  Полиця показує одну картку на твір, сторінка книжки всі видання з кнопками, записи в бібліотеці йдуть на твір.
- Серії: томи з номером у назві («…, том третій», «…. Том 2. …») або комплект (сексталогія, трилогія, комплект)
  на одній полиці згортаються в одну картку (комплект, інакше перший том); кожен том має свою сторінку, і на
  кожній є список томів. Номери для серій без нумерації в назвах: `volumes` у `seed/matches.json`.

Запуск: `WEB_LOGIN_TOKEN=… npm run platform`, далі відкрити `/login/<token>` раз, і браузер залогінений.
Деплой: окремий Fly-застосунок `chytai-web` (`web/fly.toml`, `web/Dockerfile`, workflow `.github/workflows/web.yml`).
- Адреси: кожен твір має одну адресу `/book/<slug>` із назви (для Books.md це самі id); id видань і старі адреси
  перенаправляють на неї (301). Slug'и будуються при старті, бібліотека зберігає записи за стабільними id.
- `/search?q=` шукає по бібліотеці і всіх полицях разом (твори, без окремих видань і томів), публічно, без входу.
